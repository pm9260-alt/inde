# 街ポーカー

街を歩いて地名カードを 5 枚集め、地名に含まれる漢字で「役」を作って得点を競う位置情報ゲームです。

地図を見て「北へ行けば東西南北がそろう」「こっちなら数字がつながる」とルートを考えるところが、このゲームの中心です。

これは**面白さを確かめるための試作版（MVP）**です。ひととおり最後まで遊べる状態になっています。

---

## 1. すぐに動かす

必要なもの: パソコンに [Node.js](https://nodejs.org/ja) 20 以上

```bash
npm install
npm run dev
```

画面に出てきた `http://localhost:5173` を開けば遊べます。

スマートフォンで試すときは、パソコンと同じ Wi-Fi につないだうえで、
表示される `http://192.168.x.x:5173` のようなアドレスを iPhone の Safari で開いてください。

> **位置情報について**
> ブラウザの決まりで、位置情報は「https のページ」か「localhost」でしか使えません。
> スマートフォンの実機で歩いて試すときは、後述の「4. スマートフォンで実際に歩いて試す」を見てください。

## 2. Google マップを表示する（任意）

キーを設定しなくても、内蔵の**簡易マップ**でゲームは最後まで遊べます。
本物の地図を出したい場合だけ、次の設定をしてください。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作る
2. 「Maps JavaScript API」を有効にする
3. 「認証情報」から API キーを作る
4. このフォルダの `.env.example` を `.env` という名前でコピーする
5. `.env` の `VITE_GOOGLE_MAPS_API_KEY=` の右にキーを貼り付ける
6. `npm run dev` をやり直す

キーが正しくないときや通信できないときは、自動で簡易マップに切り替わります。アプリは止まりません。

---

## 3. ランキングを全員で共有する（任意）

設定しない場合、ランキングは**この端末の中だけ**で集計されます（それでも今日・今週・全期間は表示されます）。

みんなでスコアを競いたい場合は Firebase を使います。

1. [Firebase コンソール](https://console.firebase.google.com/) でプロジェクトを作る
2. 「Firestore Database」を作成する
3. 「プロジェクトの設定 → 全般」で**プロジェクト ID**と**ウェブ API キー**を確認する
4. `.env` に次を書く

```
VITE_FIREBASE_PROJECT_ID=あなたのプロジェクトID
VITE_FIREBASE_API_KEY=あなたのAPIキー
```

5. Firestore の「ルール」を次のようにする（試作版向けの簡易ルールです）

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /machiPokerScores/{document} {
      allow read: if true;
      allow create: if request.resource.data.score is int
                    && request.resource.data.score >= 0
                    && request.resource.data.score < 1000000;
      allow update, delete: if false;
    }
  }
}
```

通信できないときは自動で端末内の記録に切り替わり、画面にその旨が 1 行出ます。

## 4. スマートフォンで実際に歩いて試す

外で歩いて試すには、https で開ける場所に置く必要があります。いちばん手軽なのは静的サイトの公開サービスです。

```bash
npm run build     # dist フォルダができます
```

`dist` フォルダを Netlify・Vercel・Cloudflare Pages などにそのままアップロードすれば https で公開されます。
環境変数（`VITE_` で始まるもの）は、そのサービスの管理画面にも同じ内容を登録してください。

iPhone の Safari で開いたあと、共有ボタンから「ホーム画面に追加」すると、アプリのように全画面で遊べます。

---

## 5. 外に出ずに開発する（位置情報デバッグ）

`npm run dev` で起動したときだけ、画面の左端に **DEV** という細いつまみが出ます。ここから、

- 現在地を好きな駅へ移動する（真上 / 取得できる距離 / 圏外）
- GPS の精度をわざと悪くする
- 位置情報を拒否された状態を再現する
- 残り時間を 30 秒にする / ゲームを即終了する
- 保存データを全部消す

ができます。**このつまみは本番ビルド（`npm run build`）には一切含まれません。**

## 6. ルールの調整

得点・役の倍率・取得できる距離・制限時間は、すべて **1 つのファイル**にまとまっています。

```
src/config/gameConfig.ts
```

よく触る場所:

| 変えたいもの | 場所 |
| --- | --- |
| 制限時間 | `GAME_RULES.durationMinutes` |
| 手札の枚数 | `GAME_RULES.handSize` |
| カードを取れる距離 | `LOCATION_RULES.captureRadiusMeters` |
| カードの基礎点 | `CARD_POINTS` |
| 役ごとの倍率 | `HAND_DEFINITIONS` |
| 役の成立条件（必要枚数など） | `HAND_RULES` |
| 複数の役が成立したときの計算 | `SCORING` |

### 得点の決まり方

```
最終スコア = カード基礎点の合計 × 倍率

倍率 = 最大役の倍率 + Σ（それ以外の役の倍率 − 1）× 0.5
```

例: 東西南北（×4.0）とペア（×1.5）が同時に成立
→ `4.0 + (1.5 − 1) × 0.5 = 4.25 倍`

5 枚そろわないまま時間切れになった場合は、倍率に 0.8 を掛けます。

### 役の一覧

| 役 | 条件 | 倍率 |
| --- | --- | --- |
| ナンバーストレート | 連続する数字を 5 枚 | ×5.0 |
| 山川 | 山 3 枚 + 川 2 枚 | ×4.5 |
| 東西南北 | 東・西・南・北をすべて | ×4.0 |
| フォーカード | 同じ漢字が 4 枚 | ×4.0 |
| 動物園 | 異なる動物が 3 種類 | ×3.5 |
| カラー | 異なる色が 3 種類 | ×3.0 |
| 同一区 | 5 枚すべて同じ区 | ×3.0 |
| スリー | 同じ漢字が 3 枚 | ×2.5 |
| ミックス | 異なる 3 カテゴリで 2 枚ずつ | ×2.0 |
| ペア | 同じ漢字が 2 枚 | ×1.5 |

ペア・スリー・フォーカードは、成立した中で**いちばん上のものだけ**を数えます。

## 7. カードデータを差し替える

いまは東京 23 区の駅 405 件を収録しています（`src/data/stations.ts`）。

全国データや公式データに差し替えるには、CSV か GeoJSON を用意して次を実行します。

```bash
npm run import:stations -- data/stations.csv
```

CSV は 1 行目を見出しにして、`駅名`・`緯度`・`経度`（あれば `都道府県`・`市区町村`）の列を入れてください。
生成された `src/data/stations.generated.ts` を `src/data/stations.ts` から読み込むように書き換えれば、そのまま全国版になります。

地名から属性（数字・方角・色・自然・動物）を読み取る辞書は `src/data/attributes.ts` にあります。1 行足すだけで属性を増やせます。

## 8. 動作確認

```bash
npm run typecheck   # 型の確認
npm test            # ルールと保存まわりの自動テスト（93 件）
npm run build       # 本番ビルド
npm run e2e         # 実際のブラウザで、ゲームを最初から最後まで通す確認（30 項目）
```

`npm run e2e` は Chromium を起動し、位置情報を差し替えながら実際に歩いたのと同じ操作を行います。
各画面のスクリーンショットが `e2e-screenshots/` に残ります。

## 9. フォルダの見取り図

```
src/
├── config/gameConfig.ts   ← 得点・役・距離・時間の設定（ここだけで調整できる）
├── data/
│   ├── attributes.ts      ← 漢字 → 属性の辞書
│   └── stations.ts        ← 東京 23 区の駅データ
├── domain/                ← ゲームのルール（画面に依存しない部分）
│   ├── cardBuilder.ts     ← 地名から属性と基礎点を作る
│   ├── hands.ts           ← 役の判定
│   ├── scoring.ts         ← 得点の計算
│   ├── handHints.ts       ← 役予告
│   ├── capture.ts         ← 取得できるかの判定（GPS 誤差を含む）
│   └── geo.ts             ← 距離の計算
├── state/                 ← ゲーム進行と保存
├── services/              ← 位置情報・保存・ランキング・地図の読み込み
├── ui/                    ← 画面
└── dev/                   ← 開発ビルド専用のデバッグ機能
```

`domain/` と `config/` はブラウザの機能を一切使っていません。
iOS ネイティブへ移すときは、この 2 つをそのまま Swift へ書き写せば、ルールは同じまま動きます。

## 10. この試作版に入れていないもの

対戦・フレンド・チャット・ガチャ・課金・広告・AR・ログインボーナスなどは、意図的に入れていません。

まず確かめたいのは次の 3 点です。

1. 地図を見て 5 枚の組み合わせを考えることが面白いか
2. 実際に歩いてカードを取った瞬間が気持ちよいか
3. 役が完成したときにもう一度遊びたくなるか
