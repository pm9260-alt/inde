# デモ表示と、3D の受け皿

---

## 1. デモ表示

季節も時刻も現在地も天候も関係なく、端末を空へ向けるだけでオリオン座が
現れます。昼でも屋内でも動きます。

### 使う

「調整」→「デモ」→ **デモ表示: 入**。
そのあと端末を **水平から 28° より上** へ向けてください。

下げる（12° 未満）と解除され、また上げれば最初から見られます。何度でも。

画面上部に「デモ表示・実際の夜空ではありません」と出続けます。人に見せる
ときに誤解が生まれないようにするためで、消せません。

### 仕組み

星の位置を作り話にはしていません。**実際の星空をそのまま剛体回転**させて、
オリオン座が端末の向いている先に来るようにしているだけです。星座の形も、
星の色も、周りの星の並びも、すべて本物のまま動きます。

基準にしているのは **東京から 2026 年 1 月 15 日 21 時に見える空**。
オリオン座が南東の空に高く、最も見慣れた姿になる時刻です。ここを固定して
いるので、いつどこで起動しても同じ絵が出ます。

回転は「星座の中心を端末の向いている先へ移し、天頂に対する傾きを保つ」
ように決めています。どの方向へ置いても逆さまになりません
（`src/sky/demoSky.test.ts` で検証しています）。

置き場所は、視野の中央から少しだけ外しています。ちょうど中央に貼りつくと
「用意されていた」感じになるので、わずかに探させます。

### 屋内で動く理由

屋内では地磁気が乱れて較正できないことが多く、本番の姿勢推定は方位を
決められません。デモは**実際の方角と合っている必要がない**ので、
そのときは重力だけで姿勢を作り、方位はジャイロだけで保ちます。

さらにデモ中は、地磁気が途中から使えるようになっても方位を磁北へ寄せません。
寄せると、置いた星座が視野からずれていってしまうためです。
（`src/sensors/attitude.test.ts` の「方位を問わない状態（デモ）」）

### 公開ビルドから外す

`eas.json` の production プロファイルで無効にしてあります。

```json
"production": { "env": { "EXPO_PUBLIC_ENABLE_DEMO": "false" } }
```

判定は `src/config/featureFlags.ts` の 1 行だけです。

```ts
export const DEMO_MODE_AVAILABLE = __DEV__ || process.env.EXPO_PUBLIC_ENABLE_DEMO === 'true';
```

`EXPO_PUBLIC_` で始まる環境変数はバンドル時に値が埋め込まれるので、
false のビルドでは条件が定数の偽になり、「調整」画面にデモの節そのものが
出ません。保存済みの設定が残っていても、読み込み時に必ず切られます。

## 2. 演出は一箇所にしかない

本番とデモで演出コードは分かれていません。どちらも
**`src/sky/staging.ts` の `evaluateStaging()`** ひとつを通ります。

```
星が現れる  →  対象の星が静かに灯る  →  星座線が順に引かれる
          →  名前が現れる  →  登場人物が出る  →  物語が始まる
```

`evaluateStaging` は「経過時間 → 見え方」を返すだけの純粋な関数です。
React にも GL にも依存しないので、動きの設計そのものを検証できます
（`src/sky/staging.test.ts`、20 件）。

本番とデモの違いは 2 つだけです。

| | 本番 | デモ |
|---|---|---|
| 空の出どころ | 実際の観測地・時刻 | 基準の空を回転 |
| 演出の起点 | 星座に端末を向けたとき | 端末を上へ向けたとき |
| 空が現れる段 | 無し（空は最初からそこにある） | 有り |

### 間の設計

値は `src/design/tokens.ts` の `staging` にまとまっています。

| 段 | 時間 | 意図 |
|---|---|---|
| 空が現れる（デモのみ） | 1400ms | ゆっくり。最初に空だけを見せる |
| **沈黙** | 500ms | ここが要。間があるかないかで、演出に意図があるかが決まる |
| 星が灯る | 1 つ 520ms / 130ms ずつずらす | 三つ星から。順序は星座ごとにデータで決める |
| 星の余韻 | 600ms かけて 45% へ戻す | 上げたままだと「選択中」に見え、「気づいた」に見えない |
| 星座線 | 1 本 260ms / 110ms ずつずらす | 三つ星から外へ。図として自然に描き進む順 |
| 名前 | 640ms | 最後の線が引き終わって 300ms 置いてから |
| 登場人物 | 900ms | 物語を開いてから |
| 神話のシート | 登場の 400ms 後 | 重ねて流す |

段を厳密に区切らず、わずかに重ねてあります。次が始まってから前が終わるほうが
流れて見えます。逆に区切りをそろえると、機械が順番に処理しているように
見えてしまいます。

**使っていないもの**: 戻り（オーバーシュート）、跳ね、パーティクル、
グロー、紫系のグラデーション。減速のイージングだけを使っています。
夜空に跳ねるものはありません。

星座線は 2 本重ねて描いています。薄い下地はそのまま残り、明るい線がその上を
伸びていきます。線が消えてから引き直されるのではなく、すでにそこにあったものが
灯っていくように見えます。

### 順序を変える

星が灯る順と、線が引かれる順は `src/data/constellations.ts` のデータです。

```ts
{
  id: 'orion',
  lines: [ [1852, 1903], [1903, 1948], ... ],  // この並びが描く順
  revealOrder: [1852, 1903, 1948, 2061, ...],  // この並びが灯る順
}
```

## 3. 3D モデルを差し込む

いまは実物のモデルがありません。代わりに**置き場所と大きさを示す枠**が、
本番と同じ間合いで現れます。モデルが用意できたら差し替えるだけで、構図も
タイミングも変わりません。枠は開発ビルドでのみ出ます。

### 置き方の考え方

星座の中の 2 つの星を「物差し」に選び、その長さを基準に決めます。
オリオン座なら三つ星です。

```ts
// src/data/figures.ts
{
  id: 'orion-hunter',
  placement: {
    baseFromHr: 1852,   // ミンタカ
    baseToHr: 1948,     // アルニタク
    heightRatio: 6.7,   // 三つ星の長さの 6.7 倍が身の丈
    liftRatio: 0.3,     // 中点から上へずらす量
    widthRatio: 0.46,   // 身の丈に対する幅
  },
  model: null,          // ← ここに GLB を差す
  motions: [
    { id: 'idle', clip: 'Idle', loop: true, speed: 1 },
    { id: 'draw-bow', clip: 'DrawBow', loop: false, speed: 1 },
  ],
}
```

角度で直接書かないのは、星どうしの角距離が観測地や時刻で変わらないためです。
星を物差しにすれば、空のどこに置いても破綻しません。

### モデルが届いたら

1. `assets/figures/orion-hunter.glb` に置く
2. `src/data/figures.ts` の該当箇所を書き換える
   ```ts
   model: {
     source: require('../../assets/figures/orion-hunter.glb'),
     nominalHeight: 1.8,
   },
   ```
3. `metro.config.js` に `glb` を資産の拡張子として足す（初回のみ）
4. GLB を描く層を `src/sky/` に足し、`SkyCanvas` の
   「登場人物の枠」を描いている箇所（`hasModel(figure)` で分岐しています）で
   切り替える

置き場所（`computeFigureFrame`）と出現の間合い（`evaluateStaging`）は
そのまま使えます。差し替えるのは「枠を描く」を「モデルを描く」に変える
一箇所だけです。

### 増やす

| 増やすもの | 触るファイル |
|---|---|
| 星座 | `src/data/constellations.ts` に HR 番号で追記 |
| 神話 | `src/data/myths/` に 1 ファイル追加し、`index.ts` に登録 |
| 登場人物 | `src/data/figures.ts` に追記し、星座の `figureId` で参照 |
| モーション | 同ファイルの `motions` に追記 |
| 演出の間 | `src/design/tokens.ts` の `staging` |

どれもデータだけで、整合性は `npm test` が機械的に検査します
（星座線の HR 打ち間違い、物差しの星が星座に属しているか、神話が指す対象が
実在するか、など）。
