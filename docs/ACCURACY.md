# 表示位置を合わせる

このアプリで最も難しいのは、見た目ではなく「画面の星が、実際の空の星と
同じ場所にあること」です。ここでは、実機でしか判断できないことを、どう確かめ、
どう報告すればよいかをまとめます。

---

## 誤差の内訳

いま分かっている誤差の要因を、大きい順に並べます。

| 要因 | 見込み | 対処 |
|---|---|---|
| 地磁気センサーの方位誤差 | **1〜15°** | 較正・磁気源から離れる・手動補正 |
| カメラ画角の想定違い | **0〜3°**（画面端ほど大きい） | 手動補正 |
| 端末の傾き（重力から） | 0.2° 未満 | 対処不要 |
| 天体計算 | 0.002° 未満 | 対処不要（自動検証済み） |
| 大気差 | 補正済み | 対処不要 |
| 年周光行差（未補正） | 0.006° 未満 | 意図的に無視 |
| 位置情報の粗さ（1km） | 0.01° 未満 | 意図的に粗く取得 |

**方位が誤差の 9 割以上を占めます。** 上下方向（高度）は重力から直接求めて
いるので、ほぼ狂いません。「横にずれるが縦は合っている」なら正常な症状です。

---

## 確認の手順

### 手順 1 — 較正する

外に出て、端末を **8 の字に大きく数回振ります**。
画面上部に「方位が定まりません」と出ていたら、それが消えるまで続けてください。

車の中、鉄骨の建物のそば、電線の下、磁石つきのスマホケースやリングは、
どれも方位を大きく狂わせます。「周囲の磁気が乱れています」と出たら、その場を
離れてください。

### 手順 2 — 方位が合っているか単独で確かめる

星を見る前に、コンパスだけを確かめます。

1. 「調整」を開く
2. 方位が分かっている目標（真南の建物、地図で確認した道路の向きなど）へ端末を向ける
3. 「いま向いている先」の **方位** を読む

ここでずれていれば、原因は天体計算ではなく方位です。
**「方位の補正」**で詰めてください。右にずれて見えるならマイナス方向へ。

> 目安: 画面上で **1° ≒ 11 ピクセル**（iPhone 15 の縦画面）。
> 画面の高さいっぱいで 68°、幅いっぱいで約 35° です。

### 手順 3 — 明るい星に合わせる

いちばん明るい星（オリオン座ならベテルギウスかリゲル、夏ならベガ）を実際に
目で探し、そこへ端末を向けます。

- **星ぜんぶが同じ向きに同じだけずれている** → 方位のずれ。手順 2 へ。
- **中央は合うが、画面の端へ行くほどずれが広がる** → 画角のずれ。
  「調整」→「カメラの画角」を動かします。
  星の間隔が実際より **広い** なら画角を **小さく**、**狭い** なら **大きく**。
- **上下だけずれる** → まず端末ケースの磁石を疑い、次に報告してください。
  高度は重力から直接求めているので、通常はずれません。

### 手順 4 — 追従の速さを見る

端末をゆっくり左右に振ってください。

- 星が遅れてついてくる → 方位の補正が効きすぎている可能性。報告してください。
- 星が細かく震える → 磁気ノイズ。周囲の金属を疑ってください。
- 上下だけ遅い / 左右だけ遅い → **設計上あってはならない症状です。報告してください。**

---

## 手動補正について

「調整」に方位と仰角の補正があります。**最後の手段です。**

| 補正 | 効く相手 | 妥当な大きさ |
|---|---|---|
| 方位 | 地磁気の偏り、コンパスの個体差 | 数度まで |
| 仰角 | カメラの光軸が筐体に対して傾いている個体差 | 1° 前後まで |

この 2 つは性質が違います。方位は**世界の側**の量（天頂軸まわりの回転）、
仰角は**端末の側**の量（端末の左右軸まわりの回転）です。片方を他方で
埋め合わせると、端末を傾けたときに合わなくなります。

補正を入れる前に必ず確かめること:

1. **複数の星で同じずれ量が出るか。** 星ごとに違うなら、原因は方位の偏りでは
   ありません。画角か座標変換を疑ってください。
2. **端末の向きを変えても同じずれ量か。** 向きで変わるなら、地磁気の局所的な
   乱れか、姿勢推定の不具合です。
3. **経路を変えても同じずれ量か。** fusion と ARKit で違うなら、姿勢推定側の
   問題です。

8° を超えるずれを補正しようとすると、精度確認画面が警告を出します。その
大きさは光軸の傾きや地磁気の偏りでは説明できないので、補正で見えなく
する前に原因を探してください。

---

## 報告のしかた

次の形で伝えてもらえれば、原因を切り分けられます。

開発ビルドなら、「精度を確かめる」画面のいちばん下に **報告用** の
まとめが出ています。そこに書かれている内容をそのまま伝えてください。

```
経路: arkit（要求 auto）
ARKit 追跡: normal
座標系の検算: 0.42°
方位 138.6° / 高度 41.2°
ゆらぎ 方位 0.08° / 高度 0.03°
ドリフト 180秒で 方位 +0.20° / 高度 +0.01°
星ずれ Vega: 右へ +4.10° 上へ -0.30°（方位 +4.30° 高度 -0.30°）
補正 方位 +0.00° / 仰角 +0.00°
画角 68.0°
偏角 -7.50°
観測地 35.681, 139.767
```

加えて、次も添えてください。

```
場所: 屋外・住宅地
機種: iPhone 15
再現性: 別の星でも同じずれ / 星によって違う
```

とくに区別したいのは次の 2 つです。

- **どこを向いてもずれ量が同じ** → 方位の系統誤差。補正値で直せます。
- **向きによってずれ量が変わる** → 地磁気の局所的な乱れ、または端末の
  地磁気センサーの較正不足。別の場所で試してもらうことになります。

## 実機でしか判断できないこと

Windows 側の自動検証（`npm test`、190 件）で押さえているのは、
座標変換・投影・姿勢推定の数学部分です。次のものは実機でしか分かりません。

1. **カメラ映像と星の重なり** — 画角の実測値。機種ごとに違います。
2. **カメラプレビューの切り取られ方** — `resizeAspectFill` を前提にしていますが、
   機種や OS の版で違いがあれば横方向の画角がずれます。
3. **地磁気センサーの実力** — 場所と端末によって数度から十数度まで変わります。
4. **描画の滑らかさ** — 60fps 出ているか、発熱で落ちないか。
5. **暗所での見え方** — 色と文字の階層が、実際の夜空の下で機能しているか。
   明るい部屋の画面で見た印象と、暗順応した目で見た印象は別物です。
6. **カメラ映像の上での可読性** — 街灯が画角に入ったときに文字が読めるか。

## 設計上、どこまで詰められるか

| 姿勢の取得元 | ゆらぎ・ドリフト | 絶対方位 | 必要なもの |
|---|---|---|---|
| `fusion` | 大きい（磁気ノイズがそのまま出る） | コンパス依存 | なし。Expo Go で動く |
| `native` | 中（Apple のセンサー融合） | コンパス依存 | 開発ビルド |
| `arkit` | **小さい**（映像の追跡を併用） | コンパス依存 | 開発ビルド |

**ここを誤解しないでください。ARKit にしても北が正確になるわけではありません。**

ARKit の `worldAlignment = .gravityAndHeading` は、セッションを始めるときの
方位をコンパスから取ります。その後はカメラ映像の特徴点追跡で姿勢を保つので、
鉄骨のそばでも揺れず、時間が経っても流れません。つまり ARKit が消すのは
**ゆらぎとドリフト**であって、**最初の方位の偏り**は残ります。

残るのはほぼ一定のずれなので、そこは手動補正で打ち消すのが筋です。
逆に言えば、ARKit にしてもずれ量が向きによって変わるなら、原因は
コンパスではなく別のところにあります。

### 経路の切り替えと比較

開発ビルドでは「調整」→「精度を確かめる」から、3 つの経路を同じ条件で
比べられます。測れるのは 4 つ。

| | 見かた |
|---|---|
| 方位・高度 | いまどこを向いていると思っているか |
| ゆらぎ | 端末を机に置いて数秒。動かしていないのに振れる分がノイズ |
| ドリフト | 置いたまま「基準にする」を押して数分。増えていく分が流れ |
| 星とのずれ | 明るい星に画面中央を合わせて「合わせた」。何度ずれているか |

経路を切り替えると、ゆらぎもドリフトも測り直します。混ぜて比べても
意味がないためです。

### ARKit の座標系の検算

ARKit 経路では「座標系の検算」という数値が出ます。これは、ARKit から得た
姿勢で重力ベクトルを世界座標へ写したとき、それがどれだけ真下からずれて
いるかです。重力は CoreMotion という**別の経路**から取っているので、
軸の読み替えを間違えていれば必ずここに現れます。

- **1° 未満** … 正常。姿勢が動いているあいだは少し増えます
- **10° 以上** … 軸の取り違え。補正で埋めずに報告してください

なお、この検算は鉛直方向の情報しか持たないので、**方位のずれは捉えられません**。
方位が合っているかどうかは、実際の星で見るしかありません。
